# Підготовка оригінальних медіа

Спочатку перевірте звіт за runtime-diagnostics (`DUB_WORK_DIR/reports/runtime.json`, або legacy local/runtime.json), source/media.csv та local/media.json. Окрема .f251.webm містить українську доріжку; поле language=eng у контейнері не є надійним визначенням мови. Не перерозпізнавати чи перекодовувати весь фільм лише для отримання опорних точок.

`python pipeline/index_keyframes.py` читає ключові packet flags через FFprobe й записує CSV. Це ключові кадри/GOP, не гарантовані монтажні склейки. Повні сцени визначайте за дією та переглядом потрібних ділянок. 1015 записів у вихідному індексі — опори для навігації.

Попередня спроба `-skip_frame nokey` з локальним VP9 почала видавати всі кадри. Не запускати її на всьому фільмі як перевірений швидкий шлях. Якщо потрібні мініатюри, спочатку мала проба/seek до окремих опор, перевірка кількості й відповідності таймкодів.

Для нарізання: `python pipeline/cut_media.py --id <ID> --start HH:MM:SS.mmm --end HH:MM:SS.mmm`, спочатку без --execute. Переконайтеся, що відео й окрема доріжка мають спільний часовий нуль. Скрипт перекодовує лише уривок для точних меж; stream copy може початися від іншого keyframe. Оригінали не змінювати. Перевірити тривалість, початок/кінець репліки й синхрон після нарізання.

У налаштованій сесії `DUB_WORK_DIR` спрямовує уривки у зовнішній exports/; можна задати `--output-dir`. Preview не створює вихідних файлів. Для короткої перевірки декодера краще null output; одноразові файли — лише зовнішній tmp/ із прибиранням після операції. Див. [сховище](../../../docs/local-workspace.md).
