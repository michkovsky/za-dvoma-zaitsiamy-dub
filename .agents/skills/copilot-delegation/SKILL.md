# Опціональне делегування Copilot CLI

## Вибір і доручення

Пропонуйте Copilot для відокремленої реалізації, дослідження з визначеними джерелами або незалежного рев’ю, коли користь перевищує передачу контексту й додаткову перевірку. Дрібні правки та задачі, залежні від усієї розмови, зазвичай виконуйте самі.

Пропозиція називає задачу, користь, очікуваний результат і суттєві витрати/обмеження, якщо вони відомі. Skill можна вибрати самостійно; запуск потребує доручення користувача на цю задачу. Поки його немає — запропонуйте й дочекайтеся відповіді. Вже надане доручення не перепитуйте; підготовка skill не дозволяє модельний запуск.

## Підготовка та передача

Прочитайте кореневі AGENTS.md, CONTRIBUTING.md та потрібну spec. Перевірте git status, базовий SHA, copilot --version і потрібні flags через --help. Не виводьте токени; встановлення CLI чи login не підтверджує модельну сесію. Не встановлюйте й не оновлюйте CLI без потреби задачі.

Працюйте у погодженій гілці. Для одночасних змін спільних файлів використайте окремий worktree під зовнішнім work_dir або працюйте послідовно. Не видаляйте worktree, поки результат не збережено. Не змінюйте користувацькі незакомічені файли поза задачею.

Завдання, журнали й експорти сесій — у зовнішньому work_dir за [правилами сховища](../../../docs/local-workspace.md), наприклад reports/copilot/<task-id>/. TEMP/TMP/кеші успадковуйте від налаштованої сесії; глобальні профілі не змінюйте. --log-dir і --share не переносять всю внутрішню історію CLI, яка може залишатися в його профілі; не комітьте її.

Передайте лише потрібний контекст звичайним текстом:

```text
Мета й режим: реалізація / дослідження / рев’ю.
База: гілка, SHA, робоче дерево; для рев’ю — точний переглянутий SHA.
Контекст: прочитай AGENTS.md, CONTRIBUTING.md, перелічені spec/tasks і джерела.
Обсяг: дозволені файли/операції, потрібний результат, що поза задачею.
Критерії готовності та перевірки: конкретні команди й очікувана поведінка.
Дозволи й виходи: потрібні tools/шляхи/мережа, зовнішній каталог журналів.
Поверни зміни, фактичні перевірки, джерела, невирішені питання,
використану модель і session ID, якщо доступні.
Не пуш, не публікуй повідомлень і не зливай PR без окремого доручення.
Не делегуй іншим агентам поза погодженим обсягом.
```

Рев’ю: читання без редагування, знахідки з доказами/файлами. Дослідження: джерела окремо від гіпотез. Реалізація: явно визначте, чи дозволені коміти; за замовчуванням очікуйте незакомічений diff.

## Запуск і контроль

Використовуйте -p/--prompt з явним -C, назвою сесії та зовнішніми --log-dir і --share=<path>. Не використовуйте default --share у поточному каталозі. Звіряйте синтаксис із локальною довідкою. Передавайте prompt як один аргумент через масив аргументів або інший безпечний механізм; не вставляйте його як shell-код. Обирайте лише підтверджений доступний model ID; auto не доводить фактичну модель.

Надавайте потрібні --allow-tool/--allow-url і шляхи під задачу; враховуйте збережені дозволи та увімкнені MCP. Read-only задача не потребує write чи GitHub mutations. --add-dir може також завантажити інструкції: додавайте лише потрібні довірені каталоги. CLI permissions не замінюють sandbox. Не застосовуйте --allow-all, --yolo, --allow-all-tools/paths/urls або assisted approval для обходу відмов. Credentials не передавайте в prompt чи flags.

У prompt mode неавторизовані tool requests можуть відхилятися без запиту користувачу. Якщо доступ, авторизація, бюджет або runtime заважають — зупиніть залежну роботу й назвіть причину; не розширюйте права та не повторюйте запуск наосліп. Після переривання перевірте процес, diff і журнали; --resume=<id> використовуйте лише для перевіреної сесії. Новий обсяг або витрати поза дорученням узгодьте.

Чекайте завершення, повідомляючи суттєвий прогрес. Exit code сам по собі не підтверджує потрібних дій. Для делегованих media/ML задач спочатку виконайте проєктну діагностику runtime.

## Приймання

Основний агент перевіряє status/diff, межі, фактичні результати перевірок і джерельні твердження. Самозвіт виконавця не є доказом; звук і відео потребують відповідної перевірки.

У PR/робочому артефакті запишіть мету, базу/переглянутий SHA, CLI version, фактичну модель або «невідома», session ID коли доступний, зміни, перевірки й обмеження. Логи залишаються локальними й автоматично не публікуються. Зауваження рев’ю — за [model-review](../../../templates/model-review.md), із рішеннями accepted/rejected/deferred та причиною.

Copilot, який реалізував зміну, не є її незалежним рецензентом. Нове рев’ю має окреме завдання/контекст для актуального SHA; обмеження незалежності назвіть. Правила PR і погодження власником не змінюються.

## Перевірені можливості

У цьому проєкті перевірено version/help CLI 1.0.107. Авторизоване виконання задач і автовиявлення skill ще не перевірені. Перший доручений запуск почніть із малої реальної задачі. У вже відкритому чаті за потреби прочитайте skill явно, не імітуючи автовиклик.

Для незнайомих flags: локальний --help, [офіційний guide](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/run-cli-programmatically) та [reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-programmatic-reference). Перевірені flags не обіцяють сумісності майбутніх версій.
