# Діагностика рантайму

З кореня запустіть `python pipeline/diagnose_runtime.py`. Прочитайте local/runtime.json, особливо unknown та помилки. Скрипт використовує стандартну бібліотеку; не завантажує моделі й не імпортує PyTorch/ONNX.

На Windows AVX/AVX2 перевіряються через OS API. FMA/F16C можуть залишитися невідомими; не підміняти їх припущенням за назвою CPU. Якщо доступний cpuinfo, його прапори доповнюють звіт. Перед вибором збірки з невідомою необхідною інструкцією перевірте її окремо доступним діагностичним засобом.

GPU/VRAM від nvidia-smi не доводять працездатності конкретного CUDA runtime. Кожну обрану бібліотеку перевіряйте в окремому процесі короткою реальною операцією; успішний імпорт чи --version не достатні. Для ASR — короткий запис, TTS — коротка репліка, GPU — обчислення/передача тензора. Фіксуйте версію, команду, exit code та результат у local/, без токенів.

Перевірка актуальності: зміни CPU/GPU, драйвера, Python, бібліотеки або binary вимагають повторної відповідної перевірки. Не повторювати важке тестування перед кожною реплікою за незмінного середовища.

Для відновлення попереднього локального стека прочитайте [історичну конфігурацію](references/legacy-runtime.md). Не застосовуйте її CPU-обмеження універсально до нових машин. Якщо binary падає з illegal instruction, припиніть масовий запуск і змініть збірку/режим; повтор того самого не допоможе.
