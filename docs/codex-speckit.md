# Spec Kit у Codex: межі інтеграції

## Вибір конфігурації

Використовуємо офіційний specify-cli з PyPI в ізольованому local/tools/spec-kit/. Інтеграція codex, скрипти py, автоматичні events=false. Залежності синтезу та системний Python не змінюються. Перевірена версія specify-cli==1.3.2 зафіксована в requirements-tools.txt.

Офіційні джерела: [встановлення](https://github.github.io/spec-kit/installation.html), [наявний проєкт](https://github.github.io/spec-kit/how-to/existing-projects.html), [Codex](https://github.github.io/spec-kit/integrations/codex.html), [синтаксис викликів](https://github.github.io/spec-kit/integrations/cli.html). Документацію перевірено 2026-11-08; опис старих slash-команд на інших сторінках не замінює інструкції встановленої версії.

## Що не можна припускати

- Codex використовує `.agents/skills/speckit-*/SKILL.md` і `$speckit-…`, а не універсальний `/speckit.…`. Не видавати назву skill за виконану термінальну команду.
- Поява файлів skills не доводить їх автоматичного виявлення в уже відкритій сесії. Перевірити доступний каталог skills; за відсутності — відкрити нову сесію в корені репозиторію. Поки цього не зроблено, агент може явно прочитати встановлений SKILL.md та виконати описані кроки, чесно позначивши цей спосіб.
- Поточний чат почався в батьківському робочому каталозі. Його автоматично наданий перелік skills не можна вважати каталогом нових skills вкладеного репозиторію. Надалі відкривати саме репозиторій як робочий каталог.
- Python-варіант скриптів обраний через спостережені обмеження Git Bash/MSYS у sandbox. Це локальна сумісність, не універсальна заборона shell-скриптів.
- `codex exec` у вкладеному workflow — окремий процес із власними вимогами до sandbox/авторизації; зараз не є перевіреним способом автоматизації. Не запускати рекурсивні агентні сесії для імітації кроку Spec Kit.
- Автоматичні обробники подій вимкнені. Не вважати, що є lifecycle gates або що skill виконається сам.
- Наявність CLI не означає, що він сам написав spec/plan/tasks: це агентні кроки за встановленими інструкціями.

## Перевірка працездатності

Потрібні фактичні результати CLI version, init, inventory/check і доступність потрібних шаблонів. Після ініціалізації порівнюємо tracked diff, зберігаємо конституцію та наші чотири доменні skills. Перевірки фіксуємо в quickstart.md першої специфікації. Непідтверджені інтерактивні можливості не позначаємо як перевірені.

## Доступ до GitHub

gh налаштовано локально, поза репозиторієм. Якщо стандартне сховище конфігурації недоступне, зовнішнє середовище задає GH_CONFIG_DIR. Не комітити hosts.yml, токени або машинні шляхи. У локальному sandbox Git credential helper через sh міг не запускатися; окремо перевіряти авторизований push, не трактувати це як потребу нового токена. Конкретний credential-bearing запуск лишається зовнішньою операцією, а не частиною Spec Kit.


## Перевірений результат у цій гілці

CLI version/check та init завершилися успішно. Установлено дев’ять speckit skills поруч із чотирма доменними. Офіційні resolve_template, setup_plan, setup_tasks і check_prerequisites працюють із Python середовища інструментів. Initial init спочатку вставив персональний шлях до Python; повторне генерування з venv Scripts на початку PATH дало переносимі python-команди. Перед свідомими змінами всі tracked SHA-256 збіглися з початковими.

Автовиявлення skills у новій сесії й вкладений codex exec досі не перевірені. У цьому чаті етапи виконані читанням установлених інструкцій. Повторювана інструкція setup — specs/001-project-workflow/quickstart.md. GitHub branch protection не вмикався.


## Зауваження після незалежного review

Copilot review виявив три дефекти згенерованих інструкцій 1.3.2. Локальні виправлення явно відділено від upstream: .specify/patches/README.md. Після init/refresh їх потрібно перевірити й за потреби повторно застосувати. Analyze/converge використовують pipeline/speckit_readonly.py, а не голий checker, який може змінити feature.json. Вимоги spec.md не скидаються при повторному specify; checklist може бути створений до плану. Звіт і межі перевірки: specs/001-project-workflow/reviews/copilot.md.
