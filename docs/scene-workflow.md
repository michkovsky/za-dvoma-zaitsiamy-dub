# Опрацювання сцен і перегляд поділу

## Побудова карти

Наступний окремий пакет робіт має зареєструвати часову основу video та audio за джерелом, скласти попередню карту всього фільму й перевірити межі. Наразі реальна карта порожня. Не вважати GOP драматичною сценою; сцена — гіпотеза про цілісну дію в часі/просторі. Зміна місця, часу, цілі чи учасників потребує пояснення за зображенням, звуком і діалогами, а не автоматичного розрізання.

Для перекладу пріоритетна цілісність голосової сцени: зв'язність реплік, відповідей, перебивань та інтонаційного й смислового розвитку. Відеосклейка й перехід звуку можуть бути рознесені в часі; голос може продовжуватися поверх нового плану або починатися до нього. На кожній запропонованій межі прослухати контекст з обох боків і зберегти повний голосовий обмін у робочому контексті перекладу. Якщо він перетинає межу облікових сцен, використати контекстні посилання й handles за чинними правилами. Така монтажна розбіжність сама по собі не означає зсуву часових шкал джерел у source/timing.csv.

Основне coverage покриває [0,duration) неперервно: сцени, титри, переходи та явно unresolved. Інтервал scene точно відповідає active-сцені; контекстні handles експорту не додають основного покриття. Межі мають докази початку/кінця й окремий стан перевірки. Виконане, неперевірене, прийняті обмеження, блокери й залишкова робота видимі без читання чату. Кількість сцен і строки уточнюються, календарних обіцянок немає.

## Окремий пакет сцени

1. Вибрати актуальні ID/revision з scenes/index.csv та джерела, зафіксувати непевність меж.
2. Створити окрему гілку для змістовної задачі. Офіційним resolver отримати складений spec-template; доповнити його templates/scene-spec.md, не замінюючи upstream. Номер feature незалежний від scene ID.
3. Явно обрати SPECIFY_FEATURE_DIRECTORY та локальний ігнорований feature pointer для цього пакета. Перед наступним етапом звіряти prerequisites, щоб випадково не працювати з іншим пакетом.
4. Пройти specify → clarify за потреби → plan → tasks → analyze → implement → converge. Один актуальний пакет на сцену, попередні доступні з історії. package у реєстрі вказує на чинну spec.md з машинним Scene binding.
5. Результат: перевірені межі й фрагмент у зовнішньому exports; учасники, український dialogue.uk.csv, README з диспозицією, дією, цілями/конфліктом/комізмом, станом на вході/виході та зв'язками. Пісня, хор, unknown, перебивання, закадрові голоси мають власні критерії та завдання. Переклад пісні не є передумовою розшифровки оригіналу.

## Зміна поділу та ручна міграція

Спершу proposed change-record за templates/scene-change.md та ребра changes/index. Для boundary — той самий ID, більша revision; для split/merge нові ID/revision=1 зарезервовані в record, але ще не в чинних реєстрах. Rejected зберігає резерв. Застаріла pending-пропозиція потребує перегляду до застосування.

До міграції перелічити **всі** зачеплені canonical-рядки, такти, пояснення, посилання, файли, SHA-погодження, пакети й завдання. Кожен має одну долю в old_ref/new_ref/decision/recheck: перенесений без змін, змінений, контекстне посилання або невирішений. Не знімати [?] і не встановлювати мовця з кадру іншого персонажа.

Переносити canonical-рядок без зміни ID та source-часу, стару копію вилучати. Переклади source_id продовжують знаходити його глобально. Такти з джерельним часом не змінюються; історичний відносний такт t_old перерахувати як old_start+t_old та явно записати нову часову основу. Репліку через межу не розрізати механічно: один власник, пояснення й контекстні refs іншої сцени.

Погодження незмінного тексту чи точного SHA — історичний факт; воно не схвалює нові межі, новий зміст або нову збірку. Старий пакет позначити заміненим, зберегти виконане й посилання на наступників; невиконані завдання явно перерозподілити без дублювання. Переглянути залежні сусідні сцени й приймання.

Applied запис, canonical-матеріали, реєстри та пакети змінюються одним комітом. Перевірити coverage, source_id й граф історії; кожну версію створює та замінює щонайбільше один applied change_id. Окремо вручну звірити повноту інвентаризації та обґрунтованість кожного винятку. Невирішені матеріали блокують оголошення міграції завершеною. Автоматичного мігратора немає. P001 не перетворюється на сцену й не змінює погоджених версій.

## Внутрішнє та міжсценове приймання

Усередині сцени зіставити текст, мовця, час, звук і зображення, диспозицію та пояснення. Відділити спостереження, правку користувача, ASR-пропозицію й інтерпретацію. Unknown лишається непевним; прийняте обмеження записується явно, не скасовує [?].

На кожному стику перевірити час, входи/виходи, предмети, рух, знання/стан, причинність, повторні згадки та наскрізні жарти. Таблиця зв'язків має scene ID і revision сусіда; зміна revision робить висновок застарілим до повторного зіставлення. Для суперечності — доказ і рішення, прийняте обмеження або видимий блокер. Нерозглянуті суперечності не ховаються за загальним «готово».

Межі, текст/мовці, пояснення, внутрішня й міжсценова перевірки мають окремі стани. Approved призначає тільки власник. Підготовка spec, проходження validator, перевірка оригіналу та погодження виконання — різні результати. Text CI не слухає звук і не підтверджує міміку.

Для автоматичного виявлення редакторського винятку README містить прозовий абзац із точним ID репліки, словами «виняток часової належності» (або «time ownership exception») та змістовним поясненням після них. У README кожної іншої сцени, яку перекриває репліка, має бути контекстне Markdown-посилання на її canonical CSV чи README власника з цим ID у підписі або anchor. Для verified/approved unknown абзац містить ID, слова «прийняте обмеження» (або «accepted limitation») та причину; реальне рішення власника перевіряють окремо. Код, порожній маркер або запис «не погоджено» не підтверджують виняток. Це вимоги до помітності редакторського запису, не мова команд у note й не автоматичне погодження.

## Перевірки й межі автоматизації

`python pipeline/validate.py`, `python -m unittest discover -s tests -v`, `git diff --check`. Реєстри та автоматичні помилки визначені в docs/formats.md і контракті 004. Редакторська повнота, джерельна правильність та доречність поділу перевіряються окремо за оригіналом. Умовні приклади в tests/fixtures/scenes/ не є розміткою фільму.
