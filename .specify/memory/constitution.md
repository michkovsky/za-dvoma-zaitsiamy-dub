# Конституція проєкту

Версія 1.0.0 · 2026-11-08. Принципи сформовані з погоджених вимог власника проєкту. Структура документа спирається на [Spec Kit](https://github.com/github/spec-kit); його CLI та повний набір команд поки не встановлено.

## I. Працюємо з наявним твором

Оригінальний фільм — джерело виконання, слів, дій і міміки. Підтверджене спостереження, правка користувача, результат розпізнавання та реконструкція мають бути розрізнювані. Не вигадувати відсутні репліки, кадри або біографічні факти під виглядом перевірених. Створення нової розкадровки не є передумовою роботи.

## II. Спільна основа, окремі адаптації

Опис оригіналу, ID персонажів і реплік та межі сцен спільні. Переклад, вимова й акторські рішення конкретної мови — у languages/<код>/. Пілоти відокремлені від хронологічної розмітки фільму. Зміна таймкоду не змінює ID.

## III. Прості формати й обґрунтовані інструменти

Markdown для описів, CSV для таблиць, JSON для машинних налаштувань. Новий формат, залежність або додатковий процес вводити за конкретної потреби. Не переносити великі галузеві схеми заради формальної відповідності.

## IV. Спочатку апаратна сумісність

Перед вибором збірок, установленням важких бібліотек або масовим запуском перевірити CPU/OS instruction support, GPU/VRAM, драйвери та доступні ресурси. Невідоме не вважати підтримуваним. Потім короткий запуск реальної операції. Повторювати перевірку після суттєвих змін середовища. Історія одного комп'ютера не є універсальною конфігурацією.

## V. Зберігаємо виконання та погодження

Смисл, комічна функція, характер, вимова, природність і візуальна синхронізація оцінюються разом. Персонаж має постійну мовну основу, а емоцію — відповідно до сцени. Погоджені варіанти не підміняти експериментами. Схвалення виконання не підтверджує непевні слова оригіналу автоматично.

## VI. Відтворюваність і пропорційна перевірка

Зберігати параметри обробки, походження еталонів і контрольні суми погоджених результатів. Скрипти виконують операції, skills пояснюють застосування й відомі пастки. Перевіряти те, що може реально зламатися: ID, час, мовців, голосові перетини, тривалість і склад збірки. Не прирівнювати автоматичне розпізнавання до прослуховування.

## Зберігання й робочий процес

Публічний Git містить текстові матеріали та інструменти. Медіа, моделі, ключі, локальні конфігурації й журнали авторизації залишаються поза Git. Значну зміну інструментарію вести через вимоги → план → завдання → виконання → перевірку. Звичайна правка репліки або картки сцени не потребує окремої специфікації.

## Зміна правил

Оновлювати цей документ разом із поясненням у docs/decisions.md та пов'язаними інструкціями. Нове рішення користувача має пріоритет; не створювати штучних погоджень для вже дорученої роботи. Ця конституція визначає правила проєкту, а не дозволи доступу до системи чи сторонніх сервісів.
