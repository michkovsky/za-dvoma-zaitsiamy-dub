# Робота ШІ над проєктом

Прочитайте `.specify/memory/constitution.md`, `CONTRIBUTING.md`, `docs/workflow.md` та `docs/formats.md`. Спілкування й документація за замовчуванням українською; перекладені репліки — відповідною мовою.

## Джерела істини

- Оригінал і правки користувача: українська розшифровка з позначенням непевності.
- `characters/index.csv`: реєстр дійових осіб. Титри пріоритетні для підтвердження наявності ролі та явного акторського зіставлення, але не нав’язують основне ім’я; правила полів — `characters/rules.md`; див. `source/character-sources.md`. Не змішувати актора без названої ролі з підтвердженим персонажем.
- `characters/`: сталі риси; `scenes/`: дія й стан конкретної сцени.
- `glossary.csv`: спільні поняття; `languages/<код>/glossary.csv`: відповіді адаптації.
- Погоджені результати й SHA-256: `pilots/<ID>/artifacts.csv` або відповідні записи сцен.
- Старі чернетки не переважають пізніші погодження. Не знімати [?] лише через правдоподібність.

## Skills

Вибирайте за поточною операцією в `.agents/skills/`:
- `runtime-diagnostics`: перед вибором/установленням медіа- й ML-інструментів та великим запуском.
- `media-preparation`: джерела, ключові кадри, нарізання.
- `voice-profiles`: еталони мовців, ідентичність голосу та conditioning.
- `scene-dubbing`: адаптація, синтез, прив'язка до міміки й складання.
- [copilot-delegation](.agents/skills/copilot-delegation/SKILL.md): оцініть користь відокремленої реалізації, дослідження чи рев’ю через локальний Copilot CLI та за потреби запропонуйте залучення. Вибір skill не запускає Copilot; потрібне доручення користувача на задачу, вже надане доручення не перепитувати.

Спочатку перевіряйте актуальний `<work_dir>/reports/runtime.json`; work_dir задає сесійний `DUB_WORK_DIR` або локальний `local/media.json`. Без обох налаштувань legacy default — `local/runtime.json`. Правила сховища — `docs/local-workspace.md`: кеші, звіти, пробні файли й exports тримати поза репозиторієм і оригіналами, без junction. Звіт дає інвентаризацію, а не автоматичний дозвіл на будь-який binary: невідомі інструкції уточнюйте, потрібну операцію перевіряйте коротко. Не імпортуйте важкі бібліотеки в основний процес діагностики.

## Зміни й перевірки

Зберігайте сталі ID. Пілот P001 не стає S001. Не вигадуйте межі сцен із GOP: ключові кадри — навігаційні опори. При створенні нового рядка репліки перевіряйте мовця, навіть коли в кадрі інший персонаж.

Запускайте `python pipeline/validate.py` після зміни таблиць. Нові/змінені скрипти перевіряйте реальною малою операцією. Великі технічні зміни описуйте в `specs/`; не створюйте специфікацію на кожну редакторську правку. Описуйте користувачу результат, відомі обмеження та наступний конкретний крок.

Не додавайте `local/`, `media/`, ваги моделей, токени й абсолютні машинні шляхи до комітів. Перед публікацією переглядайте склад diff. Не оголошуйте повну відтворюваність, поки залежності та всі входи генератора не перенесені й не перевірені.


## PR і Spec Kit

Усі зміни — в окремій гілці та PR. Не пушити в main і не зливати PR без явного погодження власника на актуальні зміни. Підготовку й перевірки виконувати автономно в дорученій задачі; погодження злиття не підміняти погодженням підготовки.

Для суттєвої задачі читайте встановлені `.agents/skills/speckit-*/SKILL.md` й дотримуйтеся послідовності з CONTRIBUTING.md. Якщо автоматична доступність skill у поточній сесії не підтверджена, явно читайте файл і називайте фактичний спосіб роботи. Не запускати вкладений codex exec для імітації виклику. Межі інтеграції: docs/codex-speckit.md.

Точкова редакторська правка може послатися на чинну специфікацію. Незалежні моделі — лише за дорученням; самоперевірку автора не видавати за їхній висновок. Не вважати CI підтвердженням якості звуку або дозволом на злиття.
