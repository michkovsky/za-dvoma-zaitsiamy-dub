# Phase 0: рішення для сценічної основи

## 1. Сцена та покриття

**Decision**: Відділити драматичну сцену від сегмента основного покриття. Покриття — неперервний ряд [start,end), прив'язаний до video; титри, переходи й нерозібрані інтервали враховуються окремо.
**Rationale**: scenes/index.csv порожній; keyframes — лише навігація. Повноту покриття можна оцінити до встановлення всіх сцен.
**Alternatives considered**: GOP як сцена відхилено. Контекстні handles експорту не рахуються додатковим основним покриттям.

## 2. Ідентичність реплік

**Decision**: Зберігати виданий ID при перенесенні єдиного канонічного рядка до нового каталогу. Префікс означає походження; поточного власника визначає розташування. Нові ID видаються з перевіркою глобальної зайнятості, старі не перевидаються. Старі каталоги зберігають опис і посилання на зміну, попередній текст доступний у Git.
**Rationale**: Конституція вимагає сталості ID. Чинний validator не вимагає збігу префікса та каталогу; source_id перекладів має розв'язуватися глобально.
**Alternatives considered**: Центральну таблицю реплік з membership, запропоновану делегованим дослідником, відкладено: чинна структура вже має потрібні canonical-файли. Копіювання тексту створює суперечливі джерела істини; перейменування руйнує посилання.

## 3. Історія та погодження

**Decision**: Split/merge видає нові scene ID, зв'язки утворюють ациклічний граф версій. Зміна меж зберігає ID та збільшує ревізію. Кожне рішення містить долю матеріалів, пакетів, посилань і погоджень.
**Rationale**: FR-005–006 потребують відновлюваної історії. Незмінний текст і точний SHA зберігають історичне погодження; нова збірка його не успадковує.
**Alternatives considered**: Перенумерація, видалення історії та автоматичне поширення погоджень відхилені.

## 4. Час і непевність

**Decision**: Явний source_id часової шкали та перевірена відповідність video/audio. Нові спостереження й такти дії мають абсолютний час джерела; старі відносні такти при зміні початку перераховуються з документованим походженням. Невстановлений speaker — unknown із поясненням, а не вигаданий character.
**Rationale**: docs/formats.md визначає час конкретного джерела; templates/scene.md наразі містить відносні такти. Validator відхиляє unknown; це треба змінити до транскрибування сцен.
**Alternatives considered**: Припущення нульового зсуву audio та визначення мовця за видимим обличчям відхилені. Якщо сталого зсуву недостатньо, потрібне окреме рішення вирівнювання.

## 5. Пакети сцен

**Decision**: Доменний шаблон доповнює офіційний складений spec-template; пакет фіксує ID і ревізію сцени, спільні правила даються посиланням. Після готовності процесу окремий пакет будує реальну карту; пакети сцен уточнюють її.
**Rationale**: Кожна сцена може потребувати тижня й повного циклу Spec Kit. Номер feature не визначає scene ID.
**Alternatives considered**: Один нескінченний список завдань для фільму та пакет на кожну репліку відхилені.

## Докази та межі

Переглянуті docs/formats.md, scenes/README.md, templates/scene.md, source/media.csv та pipeline/validate.py. Validator зараз перевіряє унікальність ID лише в межах CSV, додатність інтервалу та відомих мовців; не перевіряє глобальні source_id, граф замін і покриття. Read-only дослідження агента підтвердило ці прогалини; запропонована ним централізація не прийнята з наведених вище причин. Зовнішні джерела й нові технології не потрібні; медіа не аналізувалися.
