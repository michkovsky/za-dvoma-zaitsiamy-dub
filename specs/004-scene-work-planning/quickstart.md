# Перевірка майбутнього процесу

## Передумови

Корінь репозиторію, доступний Python 3.10+ (Store alias може не працювати). Інтерпретатор звірити з актуальним зовнішнім reports/runtime.json. Медіаоперації для цього пакета не потрібні. Прочитати [модель](data-model.md) та [контракт](contracts/scene-records.md).

## Доступні зараз перевірки

```powershell
$env:SPECIFY_FEATURE_DIRECTORY='specs/004-scene-work-planning'
python pipeline/speckit_readonly.py --json --require-spec
python pipeline/validate.py
git diff --check
```

Очікування: визначений пакет 004, наявні spec/plan, чинні таблиці не пошкоджені, whitespace errors немає. Нові формати цими перевірками ще не підтверджуються. Не вимагати tasks до відповідного етапу.

## Після implement: автоматичні сценарії

Майбутня команда: `python -m unittest discover -s tests -p test_scene_validation.py -v`. Набір у цьому PR не створюється. Умовні fixtures мають власний root і не пишуть у канонічні scenes/. Тимчасові виходи — зовнішній work_dir за docs/local-workspace.md.

| Сценарій | Очікування |
| --- | --- |
| Джерело 120 с: unresolved [0,20), S001 [20,60), S002 [60,110), credits [110,120) | 100% основного покриття, 20 с явно нерозібрані; аналіз не оголошений готовим. |
| Межа 60→65 с між S001 і S002 | ID ті самі, нові ревізії обох сцен, coverage оновлений, повторні перевірки видимі. |
| Split S001 → S003/S004, S001-L001 переходить у S004 | ID репліки збережений один раз; source_id перекладу й performed розв'язуються глобально. |
| Merge S003/S004 → S005 і повторний поділ | Ациклічна історія; нові ID сцен; виконане та залишкове не дублюються; погодження незмінних частин збережені. |
| Репліка перетинає межу | Один canonical-власник, явний виняток і контекстне посилання; немає подвійного основного обліку. |
| Зміна початку сцени зі старими відносними тактами | Такти приведені до джерельного часу без зміни положення подій у фільмі. |
| Unknown і хор | Unknown з note лишається непевністю; без note та невідомий ID у хорі відхиляються. |
| Audio offset +2 с | Перевірка після приведення часу до video; відсутня відповідність не стає нульовою. |
| Дублікат репліки, dangling source_id, gap/overlap, невідоме джерело, цикл, неправильні наступники | Кожна окрема негативна fixture відхиляється ненульовим кодом. |
| Порожня карта | Початковий стан дозволений; повідомлення «покриття не побудовано». |
| Proposed split/merge із новими наступниками тільки в change-record/index | Пропозиція валідна, поточні scenes/index і coverage незмінні; applied без реєстрації наступників відхиляється. |
| Негативна CSV/JSON-fixture в tests/fixtures/ | Загальний validator її не читає; ізольований тест відхиляє її. Та сама помилка в канонічних даних відхиляється загальною перевіркою. |
| Record із точними Change metadata/Before/After; повторний/відсутній блок або некоректний CSV | Коректний запис читається однозначно; кожний пошкоджений варіант відхиляється, довільний текст не підміняє машинні поля. |
| Snapshot не відповідає ребрам, метаданим або іншому опису наявної версії | Діагностика конкретної невідповідності; історичні snapshots не порівнюються з новішою поточною ревізією. |
| Proposed boundary r1→r2, rejected split та застаріла pending-пропозиція | Boundary не вимагає нового ID; rejected зберігає резерв ID; застаріла пропозиція потребує перегляду й не змінює карту. |

## Після implement: редакторське приймання

1. За доменним доповненням та офіційним складеним spec-template створити умовний пакет звичайної сцени й пакет із піснею, закадровим мовленням і непевним мовцем. Перевірити всі результати FR-009, критерії та посилання на спільні правила.
2. На умовній парі сцен пройти внутрішню й міжсценову перевірку: час, учасники, рух, цілі, знання, причинний зв'язок і наскрізний жарт. Кожна суперечність має рішення або видимий блокер.
3. Звірити перелік матеріалів до/після зміни, пакети й завдання. Новий монтаж окремо потребує погодження.
4. Перевірити diff для P001 та погоджених мовних матеріалів: небажаних змін немає. Text CI не підтверджує звук чи міміку.
