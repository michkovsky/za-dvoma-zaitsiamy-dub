# Feature Specification: Зовнішній робочий каталог

**Feature Branch**: 002-external-workspace
**Created**: 2026-11-08
**Status**: Draft
**Input**: Налаштувати медіа й рантайм; не залишати тимчасове сміття у Videos/2V та репозиторії. Користувач обрав source/work/2V; без junction і AppData.

## User Scenarios & Testing

### User Story 1 — Чисті вихідні папки (Priority: P1)
Власник зберігає оригінали й Git-копію чистими, а робочі файли знаходить у погодженому каталозі.
**Independent Test**: Діагностика записує звіт поза репозиторієм; preview нарізання не створює медіа.
**Acceptance Scenarios**:
1. Given зовнішній каталог обрано, when запускається діагностика, then звіт створено там і немає local/runtime.json у репозиторії.
2. Given preview уривка, when показано команду, then ціль вказує на зовнішній exports і файл ще не створено.

### User Story 2 — Відтворюване локальне середовище (Priority: P2)
Власник відкриває робочу сесію з налаштованими медіа, Python і зовнішніми кешами без системних змін.
**Independent Test**: Сесійний launcher задає TMP/cache paths лише своєму процесу; джерела декодуються короткою операцією без пробних файлів.
**Acceptance Scenarios**:
1. Given запуск локальної сесії, when виконано launcher, then робочі шляхи відомі, bytecode не засмічує код, глобальний профіль не змінено.
2. Given незаданий зовнішній каталог, when старий виклик використано, then попередні defaults збережені.

### Edge Cases
Не видаляти існуючі результати; не перезаписувати оригінали; невідомі CPU flags залишати unknown; параметр явно заданого виходу переважає сесійний default. Немає automatic cleanup старих невідомих файлів.

## Requirements
### Functional Requirements
- FR-001: Робочі звіти, кеші, tools, tmp та exports MUST бути поза оригіналами й Git; репозиторій може містити малу ігноровану конфігурацію шляхів.
- FR-002: Діагностика MUST підтримувати явний шлях виходу та зовнішній сесійний default без обов'язкового запису у local/. Звіт має суфікс .json; work_dir і виходи всередині каталогів налаштованих оригіналів MUST відхилятися до запису.
- FR-003: Нарізання MUST підтримувати зовнішній каталог виходу; preview не створює каталогів чи медіа, а execute зберігає заборону перезапису.
- FR-004: Старі виклики без нового налаштування MUST зберегти попередню поведінку; явний параметр має вищий пріоритет за сесійне налаштування.
- FR-005: Локальне налаштування MUST не створювати junction, не змінювати системні env/profile й не переносити оригінали.
- FR-006: Перед роботою MUST отримати фактичний runtime inventory і коротко перевірити декодування; невідомі властивості не вважати підтвердженими.
- FR-007: Тимчасові файли поточної установки MUST бути прибрані після перевірки; матеріали іншої роботи не видаляються.

### Key Entities
Media mapping — локальні шляхи до окремого відео/аудіо. Work directory — зовнішні reports/cache/tmp/tools/exports. Runtime report — інвентаризація, не сертифікат сумісності моделей.

## Success Criteria
- SC-001: Після перевірки в оригінальному каталозі ті самі три файли; у Git немає нових кешів/пробних медіа.
- SC-002: Звіт і preview посилаються на обране зовнішнє сховище; 7 вимог мають завдання й перевірку.
- SC-003: Власник отримує одну відтворювану команду початку сесії; зміна надана PR без злиття.

## Assumptions
Погоджений локальний каталог source/work/2V; його персональні абсолютні шляхи не комітяться. Середовища ML і старі експерименти зараз не мігруємо. Закріплений launcher і конфіги — корисний локальний стан, а не одноразові тимчасові файли.
