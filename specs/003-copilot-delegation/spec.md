# Feature Specification: Опціональне делегування Copilot CLI

**Feature Branch**: `003-copilot-delegation`
**Created**: 2026-11-08
**Status**: Draft
**Input**: Skill, за яким агент оцінює доречність Copilot та пропонує залучити його до виконання роботи, а не лише рев’ю.

## User Scenarios & Testing

### User Story 1 — Вибір виконавця (Priority: P1)

Агент може помітити користь делегування й запропонувати його власнику, не запускаючи виконавця автоматично.

**Why this priority**: Опціональність і контроль користувача — основна потреба.
**Independent Test**: Порівняти ізольовану задачу, дрібну правку та вже доручене делегування без зовнішнього запуску.

**Acceptance Scenarios**:
1. **Given** відокремлена задача, **When** делегування корисне, **Then** пропозиція називає обсяг, користь і результат; за відсутності доручення чекає погодження.
2. **Given** дрібна правка, **When** передача контексту дорожча за виконання, **Then** агент працює сам.
3. **Given** явне доручення залучити Copilot, **When** обсяг не змінився, **Then** повторне погодження не потрібне.

### User Story 2 — Виконання та приймання (Priority: P2)

Після доручення Copilot отримує достатній контекст і межі, а основний агент перевіряє результат.

**Why this priority**: Делегування має давати прийнятні артефакти без сміття в джерелах.
**Independent Test**: Скласти за інструкцією завдання реалізації та окремого рев’ю й перевірити повноту передачі та приймання без платної сесії.

**Acceptance Scenarios**:
1. **Given** задача реалізації, **When** готуємо запуск, **Then** визначені файли, базовий коміт, критерії, перевірки, дозволи та зовнішнє сховище журналів.
2. **Given** результат, **When** приймаємо роботу, **Then** перевіряємо diff і результати та не видаємо звіт виконавця за незалежне рев’ю.
3. **Given** недоступний CLI, авторизація чи дозвіл, **When** запуск неможливий, **Then** причина видима, успіх не імітується й доступ автоматично не розширюється.

### Edge Cases

- Спільні файли: окремий worktree або послідовна робота.
- Перервана сесія: перевірити фактичні зміни перед продовженням.
- Конфіденційний контекст: передавати лише потрібне, журнали залишати поза Git.

## Requirements

### Functional Requirements

- **FR-001**: Skill MUST бути доступний для вибору агентом і явного виклику; завантаження не дозволяє запуск Copilot саме по собі.
- **FR-002**: Пропозиція MUST оцінювати користь, передачу контексту й результат; запуск MUST чекати доручення, якщо його ще немає.
- **FR-003**: Інструкція MUST покривати реалізацію, дослідження та рев’ю і передачу контексту, меж, перевірок та правил проєкту.
- **FR-004**: Дозволи MUST відповідати задачі; повний доступ автоматично не надається, правила публікації й злиття не змінюються.
- **FR-005**: Журнали й тимчасові артефакти MUST бути поза Git та оригіналами; спільні файли змінюються послідовно або в окремих робочих деревах.
- **FR-006**: Основний агент MUST перевіряти результат, розрізняти реалізацію та незалежне рев’ю, фіксувати фактичного виконавця й обмеження.
- **FR-007**: Документація MUST відділяти перевірені можливості CLI від неперевіреного авторизованого виконання й описувати зупинку та відновлення після помилок.

### Key Entities

- Пропозиція: задача, користь, результат, стан доручення.
- Завдання: контекст, база, межі, критерії та дозволи.
- Результат: зміни, перевірки, виконавець/сесія, невирішені питання, рішення основного агента.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Три сценарії вибору дають однозначну дію без зайвого запуску чи повторного погодження.
- **SC-002**: Для реалізації та рев’ю можна скласти повне завдання й план приймання за однією інструкцією.
- **SC-003**: Зміна надана окремим PR із перевіреною структурою skill, без нових журналів, медіа чи машинних конфігурацій у Git.

## Assumptions

- Skill належить проєкту й розміщується поруч з іншими skills.
- Підготовка skill не доручає запуск платної модельної сесії.
- Автовиявлення в поточному чаті не припускається; можливе явне читання.
- Обгортка CLI, scheduler і зміни конституції не потрібні.
